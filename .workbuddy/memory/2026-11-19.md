### 真正根因：App Sandbox 缺 network.client（用户第二次反馈仍连不上）
上面的"验证通过"是**假阳性**：只 curl 了后端（后端在沙箱外，当然正常），从没让前端真发请求。前端报"无法连接后端（baseUrl）"是 api_client.dart:428 的 ApiException。

真因：`GC-UI/frontend/macos/Runner/Release.entitlements` 只开了 `com.apple.security.app-sandbox=true`，**没有 `com.apple.security.network.client`**。沙箱内进程向 127.0.0.1:17890 发起出站 HTTP 会被内核拒绝(EPERM)，所以发布版前端连不上；DebugProfile.entitlements 有 network.server 所以开发时正常，掩盖了问题。用 `codesign -d --entitlements :- GC-UI.app` 可确认签名里只有 app-sandbox。

修复：给 Release.entitlements 加 `network.client` + `network.server` → 重新 `flutter build macos --release`（新签名自动嵌入）→ 替换 GC.app 内 GC-UI.app → 重打包。

**这次验证到位**：`open GC.app` 后 `lsof -nP -a -p <前端PID> -iTCP` 显示 `GC-UI ... TCP 127.0.0.1:60082->127.0.0.1:17890 (ESTABLISHED)`——前端真连上了。这才是"打开即连好"的硬证据。

最终交付覆盖更新：`dist/mac-arm64/GC-1.1.1-mac-arm64.zip`（72MB，sha256 `2b0f4c25ce4e52edf18a45ceb2fe2f91612757db5589f346ffd984665cab5172`），包内前端签名已含 network.client/server。

教训：验证桌面端"连后端"必须看**前端进程的网络连接**（lsof），不能只 curl 后端。无 GUI 会话时 screencapture/AppleScript 不可用。

### 模型无法启动 + 后端崩溃（PR #29）
**根因**：macOS 的 AppKit 要求 NSApplication 在**主线程**。Flutter 模式下 `FlutterShell` 用 `ui.WaitForExit()` 占住主线程，而 `AvaloniaHost` 在 `new Thread(...)` 副线程里跑 `StartWithClassicDesktopLifetime`。点「启动模型」时模型窗口在副线程触碰 AppKit → 进程级崩溃，后端随之消失（表现为"无法启动模型"+"后端容易崩溃"）。纯 Avalonia 版不受影响，只在 Flutter 打包模式暴露。

**修复**（4 文件，+114/−51）：
- `AvaloniaHost`：新增 `RunOnCurrentThread()`/`Shutdown()`，`EnsureStartedAsync()` 改为只等 `_ready`，不再自建线程。
- `BackendServer.Start(args, port, out AvaloniaHost)` 重载（out 参数不能在 lambda 里用，内部用局部 `host`）。
- `FlutterShell`：前端拉起后在主线程跑 Avalonia 事件循环，`ui.Exited` 时后台 `Shutdown()`；Avalonia 不可用时退化 `WaitForExit()`。
- `Program.cs`：`app.StartAsync()` 后主线程跑 Avalonia，失败则 `WaitForShutdown()`（需 `using Microsoft.Extensions.Hosting`）。

**验证**：`/api/health` → `uiAvailable:true`；前端 `ESTABLISHED →17890`；`POST launch` → `HTTP 200 {"ok":true,"message":"已启动模型 contour-map"}`；启动后后端存活。

## contour-map 模型重写（对照加密 HTML 课件移植）

**背景**：用户提供的 `~/Downloads/等高线及地形部位演示.html`（79MB）是授权壳 + AES-256-GCM + gzip 的课件，内含 Three.js 版五大地貌演示。已在本地用 node 复现解密（key = 两数组异或，AAD `QLAB|contour-landform-reading|...`），还原出 83MB 内部课件；其内容为「10 张内嵌 PNG + 切割视频 + 标注层」，并非可交互 3D。按用户要求改为在 `model/contour-map` 用 C#/Avalonia 重写。

**改动文件**（均在 `model/contour-map/src/`）：
- `TerrainField.cs`：新增 `LandformKind`（Peak/Ridge/Valley/Saddle/Cliff）与五个高度场生成器。要点是地形要**宽阔**（穹状山体、宽脊、V 形谷、双峰垭口、台地陡崖），半径过小会变成“尖锥/薄墙”。
- `ContourView.cs`：重写为可交互 3D（拖动旋转、滚轮缩放），四步实验（切割/成线/投影/判坡），俯视/立体切换，自动取景 `UpdateCamera`（按包围盒八点投影铺满画布），法线光照，裙边侧壁，分层设色在 3D 用 `ColorForHeightSmooth` 平滑过渡、俯视仍用硬分档。
- `ContourPage.cs`：地貌标签移到画布上方（WrapPanel，窄屏自动换行）；右侧栏 344px，<980px 自动隐藏；四步流程/观察面板/判读要点；底部播放、重置、视图切换、上色、实时读数；空格与 1–5 快捷键；全屏。
- `DefaultTexts.cs`：90 个键，中英各一套。
- `ContourMapRuntime.cs`：`LoadTexts` 改为「内置默认 + i18n/*.json 覆盖」，之前完全忽略语言包。
- 清单 `contour-map.json` 版本 1.1 → 1.2；`help.json` 同步新交互。

**修掉的真实 Bug**：
1. `ExtractContour` 的 `Chain()` 只向尾部延伸，一条等高线被切成大量短链 → 3D 里显示成**虚线等高线**。改为端点索引 + 双向延伸后，每层只剩 1 条 300+ 点的完整曲线。
2. `SlopeAt` 固定除以 450，导致山体坡度全饱和为 1（整片红），“疏密判坡”失效。改为按 `span*2.6` 自适应归一化。

4. 切割时山峰标注悬在切面上方 → 高于切面的山峰不再标注。
