# 2026-11-14

## GC 启动器安全加固（补完）

- **GC-SAVEDOG 裁剪发布**：`PublishTrimmed=true` + `TrimMode=full` +
  `JsonSerializerIsReflectionEnabledByDefault=false`（已写进 csproj 与两套构建脚本）。
  体积 70MB → 14MB。裁剪后反射式 JSON 会失效，因此新增
  `GC-SAVEDOG/SavedogJson.cs`（`JsonSerializerContext` 源生成）并通过
  `Json.TypeInfoProvider` 钩子接进共享的 `GC.Download/GC.Services.Json`。
  → 新增 JSON 类型必须登记到 `SavedogJsonContext`，否则只有发布产物会炸。
- **构建产物布局改为 `dist/<系统>-<架构>/`**（mac-arm64 / win-amd64 / win-arm64），
  更新包路径 `dist/<平台>/GC-<版本>-<平台>.zip`；`pack_launcher` 之后调
  `VersionStamp --launcher-only` 把 `path/dir/name/sha256/size` 写进清单并重新签名。
  原始 `.app`/`.exe` 移到 `build/trash/`（避免递归删除几百个文件）。
- **启动器更新支持「只发产物、不发 Release」**：新增 `GC-DOWNLOAD/LauncherArtifacts.cs`
  （平台标签/别名、候选目录与文件名推导，构建端 VersionStamp 也链接同一份）。
  `GitCodeRemote/GiteaRemote/DirectoryRemote.DownloadPackageAsync` 改成
  多候选尝试：url → 清单 path → `dist/<系统>-<架构>/` 目录扫描 → dist 根目录命名，
  每个候选都必须匹配已签名清单的 sha256。
  `GitCodeReleaseRemote` 在「没有 Release」时不再清空 launcher 字段（清单已签名）。
- **测试**：`--update-test` 新增两条用例（dist 目录能找到并下载 / dist 目录里哈希不符被拒绝），
  当前 33 项全部通过。
- 触发过的坑：`rm -rf` 大批文件被沙箱批量删除保护拦截 → 构建脚本改用 `mv` 到 `build/trash`。
